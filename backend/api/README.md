# Partaay Event API — H2 first, PostgreSQL ready

This starter implements a first event-management API with Spring Boot, JPA, Flyway, H2, and integration tests.

## Requirements
- JDK 21
- Maven (or use the included Maven Wrapper if generated by Spring Initializr)
- Internet access the first time Maven downloads dependencies

## Run
From this folder, use an installed Maven 3.9+:

```powershell
mvn spring-boot:run
```

This starter ZIP does not include Maven Wrapper scripts. If you prefer the wrapper, generate or add it with Maven Wrapper after opening the project.

Health endpoint:
- http://localhost:8080/actuator/health

## Run tests
```powershell
mvn test
```

## API examples

Create an event (uses the seeded test host UUID only when running tests; insert a matching user in the development DB before creating an event):

```json
{
  "hostId": "11111111-1111-4111-8111-111111111111",
  "title": "Saturday Party",
  "description": "Bring your friends",
  "startsAt": "2027-01-15T18:00:00-05:00",
  "endsAt": "2027-01-15T22:00:00-05:00",
  "venueName": "Community Hall",
  "city": "Charlotte",
  "visibility": "PUBLIC",
  "capacity": 40
}
```

`POST /api/events` — create an event  
`GET /api/events` — list scheduled public events  
`GET /api/events/{id}` — get a scheduled public event; private events return 404  
`PUT /api/events/{id}` — update an event

## Important security note
This is a development starter, not production-ready. Authentication and authorization are not implemented yet. In particular, `POST` and `PUT` currently accept a supplied `hostId`, and `PUT` does not yet verify host ownership. Do not expose this API publicly or use real user data until authentication, authorization, and host ownership checks are implemented. Private-event details are intentionally excluded from public list/detail endpoints.

## PostgreSQL migration
The DDL is in `src/main/resources/db/migration/V1__create_users_and_events.sql`. The migration uses UUIDs, `TIMESTAMP WITH TIME ZONE`, constraints, and indexes supported by PostgreSQL and H2 PostgreSQL mode. H2 compatibility mode does not guarantee identical behavior; add a real PostgreSQL integration test before production. Switch the datasource URL, driver, username, and password through environment-specific configuration rather than changing the migration.
